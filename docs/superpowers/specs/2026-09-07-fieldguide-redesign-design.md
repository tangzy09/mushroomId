# 菌菇图鉴改版：以查阅为主，游戏为辅

> 日期：2026-09-07 · 版本：v2（自审后修订）· 状态：设计稿，待批准
> 依据：fishId 2026-08 同类改版的实证经验（`~/.claude/skills/species-field-guide`），
> 本项目 `docs/design/DESIGN.md` v0.3，以及对 `data/mushrooms.json` 的体检结果（`checkup.mjs`）。
>
> v2 修订：离线提到一期（山里断网是常态）；识别要点分毒种先行；毒/可食差异句强制人工；
> 轮廓提为第一路、菌盖背面改条件维度；颜色路常驻警示；图鉴只显示现实状态；
> 加全字段搜索；分享卡改用照片；分期切成 A/B/C。

## 0. 一页结论

| 问题 | 决定 |
|---|---|
| 产品是什么 | **口袋菌菇图鉴**：181 种真实照片配名字，从「现场看得见的特征」查到「它叫什么、怎么认、别和什么混」。答题是练习工具，菌菇园是附赠玩法。 |
| 为什么改 | 现在是「选林地 → 答题 → 抽卡」的收集游戏，没抽到的种在图鉴里显示 `???` 不能点。**查阅路径被玩法埋了**，和 fishId 改版前一模一样。 |
| 核心前提 | **要查的人往往不知道它叫什么。** 首页不是搜索框，是从可见特征出发的入口，条件可叠加。 |
| 场景前提 | **查的地方往往没信号。** 采菇人在山里查手机，离线是一期必需，不是二期功能。 |
| 三个已定的决定 | ① 菌菇园/抽卡保留，退到「我的」里当一个玩法；② 检索从可见形态出发；③ 识别要点由 AI 据公开资料写初稿并如实标注，不做「能不能吃」的结论。 |
| 分期 | **一期 A**（查阅路径打通，一周可上）→ **一期 B**（五路检索）→ **一期 C**（数据补全）→ **二期**（观察日志、训练重构）。 |
| 不变的红线 | 不做拍照识别；`edibility` 只转述公开资料且必配 `note`；不做「看图判断能不能吃」的任何玩法或筛选；不写采摘烹饪去毒；不写药用功效；不用颜色暗示毒性。 |

## 1. 信息架构

底部导航从「菌菇园 / 图鉴 / 我的」改为 **「图鉴 / 我的」** 两个 tab。

```
图鉴（首页）─ 顶部搜索框（全字段）
            ─ 五路检索 ─ 详情页 ─ 测一测 / 分享名片
                            └ 相似种 → 另一个详情页 → 返回回到上一个
我的 ─ 🌲 菌菇园（入口卡显示园里几株、待收孢子；进去是原游戏全套）
     ─ 🎯 认菌训练（二期）
     ─ 📓 我见过（二期）
     ─ 设置 / 存档迁移 / 急救卡 / 关于
```

- 图鉴里 **181 种全部可查可点**，不再有 `???` 和锁。
- **图鉴是现实图鉴，游戏状态不进图鉴。** 格子上不显示「已收集」；将来只显示「我见过」（二期）。「已收集」只在菌菇园里有意义。
- 菌菇园及其附属（孢子、腐殖质、每日任务、合成、菌篮、菌种库）整体搬进「菌菇园」二级页，**代码不动，只换入口**。`Storage.collections` 语义不变，存档不需要迁移。
- 页面栈：`show()` 现在是平铺切换，改版后要支持「详情 → 相似种详情 → 返回」多级返回，改成栈式。fishId 的 `guide.js` 有现成实现。⚠ `show()` 被十几处调用，这是一期 A 里最需要小心的重构，要有行为验收兜底。

## 2. 首页：搜索框 + 五路检索 + 叠加筛选

**顶部一个搜索框**，搜全字段：中文名、别名、学名、英文名、拼音、科、生境、基质关键词。已知名字或知道「长在松树下」的人从这里走，成本低、价值高。

**五路检索**：五个 tab 不是五个页面，是**同一份 `FILTER` 的五个编辑入口**。引擎直接拷 skill 里的 `facet.js`，它已经和 fishId 的手写实现对拍过 59400 次逐值一致，**不要重写**。

| 顺序 | 入口 | 字段 | 值 | 为什么排这里 |
|---|---|---|---|---|
| ① | **轮廓** | **新字段 `silhouette`**，从 `art.cap` 31 值归并 | 伞形 / 漏斗喇叭 / 贴树架子 / 球块 / 珊瑚枝状 / 棒指 / 脑蜂窝 / 耳与胶质 | **对所有形态都有效**。真实鉴定是先看整体再翻背面。剪影由 `ShroomArt` 画组代表 |
| ② | **菌盖背面** | `hymenium` | 菌褶 90 / 菌孔 27 / 菌齿 6 / 棱脉 6 | **条件维度：选了「伞形」或「漏斗喇叭」才出现。** 马勃、地星、珊瑚菌、胶质菌没有背面，硬摆出来三成物种会落进「光滑 / 内部」两个含糊桶 |
| ③ | 长在哪 | `substrate` | 木上 62 / 树根共生 60 / 土上 21 / 草地 17 / 落叶 14 / 虫体与寄生 6（归并） | 与形态几乎正交，两刀下去收敛最快 |
| ④ | 颜色 | **新字段 `colorGroup[]`**，多选 AND | 白 / 黄 / 橙 / 红 / 褐 / 灰黑 / 紫蓝 / 绿 / 粉 | 人人答得上。**tab 顶部常驻一句「颜色不能判断毒性，且会随干湿和成熟度变化」**——这是红线 6 的落点 |
| ⑤ | 名字 | `name` / `pinyin` / `pyAbbr` / `latin` / `nameEn` | 全宽索引列表 + 拼音索引条 | 已知名字的人的快捷道 |

**幽灵 chip**（不占常驻位，点开弹层）：`＋ 菌环菌托`（有环 36 / 有托 21，认鹅膏最要紧的一刀）、`＋ 当季`（默认预置当月）。

**⛔ 没有「食性」这一路，也没有「可食」筛选。** 只在弹层里提供一个 `☠️ 有毒与剧毒` 开关，用来学毒菌，不用来找能吃的。

四条硬规矩，每条都有验收断言：

1. **切 tab 不清筛选。**
2. **剩余计数**：每个类目显示「其余条件不变时还剩几种」，为 0 置灰不可点。
3. **收敛到位切网格**：活跃条件 ≥ 2 且结果 ≤ N 时切两列大图网格，每格配该种第一条识别要点。N 按 181 种的实际分布调，先定 8。
4. **毒种对照提示**：结果集里同时含 `poisonous/deadly` 与其它食性的种时，顶部常驻「这组里有毒菌，它们和可食种可能长得一样」；毒种标记在任何列表里永远显示。

布局：左右分栏 53 / 47，手机竖屏也分栏；「名字」tab 全宽。

## 4. 相似种

`lookalikes` 已双向且校验器有门。差异句分两级：

- **一般配对**：自动取对方的 `idKeys[0]`，几百句白拿。
- **⛔ 毒/可食配对（任一方是 `poisonous/deadly`，另一方不是）**：差异句**必须人工写进 `SIMILAR_DIFF`**。「特征」不等于「区别」，死帽菇的第一条要点未必是它和橙盖鹅膏的区别所在。校验器加门：这类配对没有人工差异句就红。

另加一门：任何 `deadly` 种的 `lookalikes` 里至少有一个非毒种，否则用户从可食种那边进来看不到警告。

## 5. 数据补齐

新增字段一览，全部进 `data/mushrooms.json`（唯一真源）：

| 字段 | 类型 | 来源与写法 | 阶段 |
|---|---|---|---|
| `idKeys` | `string[3]` + 每条 `src` | 见下 | 毒种 42 种 → 一期 A；其余 139 种 → 一期 C |
| `silhouette` | 枚举 8 组 | 从 `art.cap` 自动映射 + 人工修正表 | 一期 B |
| `colorGroup` | `string[]` 1–3 个 | 按已选照片主色标注 | 一期 B |
| `capCm` | `[min, max]` | 从 Wikipedia 描述取，取不到留空 | 一期 C |
| `pinyin` / `pyAbbr` / `initial` | string | `pypinyin` 自动生成，多音字修正表 | 一期 B |
| `encounter` | 枚举 4 档 | iNat 观察数分档：≥10000 常见 / 1000–9999 偶见 / 100–999 罕见 / <100 难得一见。**本土种人工修正**：菜市场买得到的一律不低于「偶见」 | 一期 A |

**识别要点的写法与来源**：一句话、现场看得见、不是检索表术语（「菌柄基部有一圈白色杯状菌托」✓，「担孢子 8–10 × 6–7 μm」✗）。每条附 `src`，优先级：① 该种 Wikipedia 中/英条目的描述段 ② MushroomExpert.com ③ iNaturalist 分类页摘要 ④ 已选定照片上的可见特征。

**⛔ 毒种先行，理由是可复核性**：42 种 × 3 句 = 126 句，是一天能逐条核对完的量。这批先写、先核、先上；其余 139 种后补。风险最高的部分缩小到可复核的规模。

**⛔ 可靠性要如实写进产品**：关于页和识别要点脚注都说明「识别要点由 AI 据公开资料整理，未经真菌学家审校，仅供学习」。这是这批数据的真实状态，不是免责套话。

同时修四条已发现的过时学名，旧名进 `aka`：
`Clitocybe dealbata → Collybia dealbata`、`Psathyrella candolleana → Candolleomyces candolleanus`、
`Lepista sordida → Collybia sordida`、`Hymenopellis raphanipes → Oudemansiella raphanipes`。

## 6. 离线（一期 A）

采菇人在山里查，没信号是常态。三层缓存，照 fishId 的 `sw.js`：

| 层 | 内容 | 体积 | 时机 |
|---|---|---|---|
| L1 核心 | HTML / CSS / 全部 JS + 数据 | 约 1 MB | install 预缓存 |
| **L2 缩略图** | `assets/photos/thumb/` 166 张 | **1.2 MB** | activate 后台预缓存 |
| L3 大图 | `assets/photos/real/` | 20 MB | 浏览时按需；设置页可一键下载 |

L2 让检索、列表、对比网格在断网时全部可用；大图拿不到时回退缩略图，详情页仍有画面。规矩照 fishId：缓存键归一化为 pathname、`CORE_URLS` 与 script 标签一一对应、大图缓存名不带版本、`?v=` 与 SW 版本串一起 bump。

## 7. 答题降级为工具

一期只改入口，二期重构：

- 详情页「测一测」：该种的 4–5 道题，复用 `Quiz`。
- 菌菇园流程里的答题**原样保留**，它是抽卡的一部分。
- 二期加「我的 → 认菌训练」：范围闪卡 / 易混对决 / 每日 5 题 / 错题本，奖励是熟练度 0–3 星。

红线不变：食性题题干先给菌名；只有看图题配照片。

## 8. 观察日志「我见过」（二期）

详情页一个按钮，**一次点击当场记一条**（日期 = 今天），再点进去才是编辑。存档新增 `seen{}` 与 `obs[]`，与 `collections` 独立。图鉴格子上显示「我见过」标记。

**不做照片，不做任何把用户照片与物种绑定的界面**，这是红线 1。GPS 只写坐标文字。

## 10. 门禁

每道门加上就反向测一次：故意破坏它守的规矩，确认它真的变红并指出是哪一条。不会变红的门只是装饰。

| 门 | 量什么 |
|---|---|
| `check_data.py` 扩展 | 新字段枚举合法；`idKeys` 恰好 3 条且附 `src`；检索表语言启发式；`silhouette` 值必须是绘制代码认得的组；`deadly` 种至少一个非毒相似种；**毒/可食配对必须有人工差异句** |
| `facet.test.js` | 引擎对拍，拷自 skill |
| 行为验收（新，走真实点击） | 页面栈多级返回 / 换 tab 不清筛选 / 计数与真实结果一致 / 零计数不可点 / 条件维度按规则出现隐藏 / 收敛切网格 / 毒种提示出现 / 搜索命中别名与生境 / 详情页照片解码且带署名 / 无照片回退绘制 / 断网后列表与检索可用 / 零 JS 异常 |
| `core.test.js` | 不变，内核扫描表不出现新领域词 |

## 12. 非目标

- 不做拍照识别
- 不做「可食」筛选、不做任何通向「能不能吃」的路径
- 不做深色模式（照片在浅底上颜色最准）
- 不重写菌菇园
- 一期不做多语言
