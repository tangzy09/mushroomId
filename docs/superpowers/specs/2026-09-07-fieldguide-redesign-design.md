# 菌菇图鉴改版：以查阅为主，游戏为辅

> 日期：2026-09-07 · 状态：设计稿，待批准
> 依据：fishId 2026-08 同类改版的实证经验（`~/.claude/skills/species-field-guide`），
> 本项目 `docs/design/DESIGN.md` v0.3，以及对 `data/mushrooms.json` 的体检结果（`checkup.mjs`）。

## 0. 一页结论

| 问题 | 决定 |
|---|---|
| 产品是什么 | **口袋菌菇图鉴**：181 种真实照片配名字，从「现场看得见的特征」查到「它叫什么、怎么认、别和什么混」。答题是练习工具，菌菇园是附赠玩法。 |
| 为什么改 | 现在是「选林地 → 答题 → 抽卡」的收集游戏，没抽到的种在图鉴里显示 `???` 不能点。**查阅路径被玩法埋了**，和 fishId 改版前一模一样。 |
| 核心前提 | **要查的人往往不知道它叫什么。** 首页不是搜索框，是五个从可见特征出发的入口，条件可叠加。 |
| 三个已定的决定 | ① 菌菇园/抽卡保留，退到「我的」里当一个玩法；② 检索五路：菌盖背面 / 长在哪 / 轮廓 / 颜色 / 名字；③ 识别要点与颜色字段由 AI 据公开资料写初稿，配免责声明，不做「能不能吃」的结论。 |
| 分期 | **一期**：信息架构 + 五路检索 + 详情页 + 游戏退位 + 数据补齐 + 门禁。**二期**：观察日志、训练重构、离线缓存。 |
| 不变的红线 | 不做拍照识别；`edibility` 只转述公开资料且必配 `note`；不做「看图判断能不能吃」的任何玩法或筛选；不写采摘烹饪去毒；不写药用功效。 |

## 1. 信息架构

底部导航从「菌菇园 / 图鉴 / 我的」改为 **「图鉴 / 我的」** 两个 tab。

```
图鉴（首页）─ 五路检索 ─ 详情页 ─ 测一测（该种的题）
                            └ 相似种 → 另一个详情页
我的 ─ 🌲 菌菇园（入口卡，进去是原游戏全套：选林地 → 答题 → 抽卡 → 定植）
     ─ 🎯 认菌训练（二期）
     ─ 📓 我见过（二期）
     ─ 设置 / 存档迁移 / 急救卡 / 关于
```

- 图鉴里 **181 种全部可查可点**，不再有 `???` 和锁。「已收集」降为格子角上一个小标记，筛选器里保留「已收集」一项。
- 菌菇园及其附属（孢子、腐殖质、每日任务、合成、菌篮、菌种库）整体搬进「菌菇园」二级页，**代码不动，只换入口**。`Storage` 的 `collections` 语义不变，存档不需要迁移。
- 页面栈：`show()` 现在是平铺切换，改版后要支持「详情 → 相似种详情 → 返回」这种多级返回，改成栈式（fishId 的 `guide.js` 有现成实现）。

## 2. 首页：五路检索与叠加筛选

五个 tab 不是五个页面，是**同一份 `FILTER` 的五个编辑入口**。引擎直接拷 skill 里的 `facet.js`，它已经和 fishId 的手写实现拿 270 条真实数据对拍过 59400 次逐值一致，**不要重写**。

| 入口 | 字段 | 值 | 备注 |
|---|---|---|---|
| 菌盖背面 | `hymenium` | 菌褶 90 / 光滑 34 / 菌孔 27 / 内部 18 / 菌齿 6 / 棱脉 6 | 翻过来看一眼人人答得上，排第一 |
| 长在哪 | `substrate` | 木上 62 / 树根共生 60 / 土上 21 / 草地 17 / 落叶 14 / 虫体与寄生 6（归并） | 与形态几乎正交，两刀下去收敛最快 |
| 轮廓 | **新字段 `silhouette`**，从 `art.cap` 31 值归并 | 伞形 / 漏斗喇叭 / 贴树架子 / 球块 / 珊瑚枝状 / 棒指 / 脑蜂窝 / 耳与胶质 | 剪影图标由 `ShroomArt` 直接画组代表，不用另做图 |
| 颜色 | **新字段 `colorGroup[]`**，多选 AND | 白 / 黄 / 橙 / 红 / 褐 / 灰黑 / 紫蓝 / 绿 / 粉 | 人人答得上的特征 |
| 名字 | `name` / `pinyin` / `pyAbbr` / `latin` / `nameEn` | 全宽索引列表 + 拼音索引条 | `pinyin` 三件套新增，可自动生成 |

**幽灵 chip**（不占常驻位，点开弹层）：`＋ 菌环菌托`（有环 36 / 有托 21，认鹅膏最要紧的一刀）、`＋ 当季`（默认预置当月，零点击先砍一半）。

**⛔ 没有「食性」这一路，也没有「可食」筛选。** 只在弹层里提供一个 `☠️ 有毒与剧毒` 开关，用来学毒菌，不用来找能吃的。这是红线 3 的直接推论。

四条硬规矩，每条都有验收断言：

1. **切 tab 不清筛选。**
2. **剩余计数**：每个类目显示「其余条件不变时还剩几种」，为 0 置灰不可点。多选维度只豁免自己（`facet.js` 已封装）。
3. **收敛到位切网格**：活跃条件 ≥ 2 且结果 ≤ 8 时，分栏换成两列大图网格，每格配该种的第一条识别要点。
4. **毒种对照提示**：结果集里同时含 `poisonous/deadly` 与其它食性的种时，顶部常驻一条「这组里有毒菌，它们和可食种可能长得一样」；毒种标记在任何列表里永远显示，不受收集状态影响。

布局：左右分栏 53 / 47，手机竖屏也分栏；「名字」tab 全宽。

## 3. 详情页

顺序照 fishId，逐块列出，每块标出它依赖哪个字段：

| 块 | 内容 | 依赖 |
|---|---|---|
| 照片 | 满宽直角，点击全屏可缩放；下方一行署名 + 来源链接（cc-by 的法律要求，已实现）；15 种无照片显示绘制并标「暂无照片，形象为示意图」 | `PHOTO_CREDITS` |
| 名称 | 中文名 / 学名（衬线斜体）/ 英文名 / 别名 | 现有 |
| 徽章 | 食性徽章 + 必配 `note`；遇见率（常见 / 偶见 / 罕见 / 难得一见） | `edibility`、**新字段 `encounter`** |
| **识别要点 ×3** | 三句现场看得见的话；脚注「据公开资料整理，仅供学习，不能作为采食依据」 | **新字段 `idKeys`** |
| 尺度对比尺 | 菌盖直径对比硬币 / 手掌 / 手臂，三档换参考物 | **新字段 `capCm: [min, max]`**（现有 `size` 是绘制缩放比，不能用） |
| 基础数据 | 科 / 生境 / 基质 / 孢子印 / 季节 / 子实层 | 现有 |
| **容易认错** | 相似种缩略图 + 名字 + 食性徽章 + 一句差异；**不折叠**；一毒一可食的对标红「一个可食一个有毒，肉眼未必分得清」 | `lookalikes` + `idKeys[0]` |
| 趣味 | `fact` + `quote` | 现有 |
| 底部操作条 | 测一测 / 分享名片 | 现有 `quiz.js`、`share.js` |

安全文案保留 `C.safety.detail`，`edibility.note` 常驻不折叠。

## 4. 相似种

`lookalikes` 已双向且校验器有门。差异句**直接取对方的 `idKeys[0]`**，几百句白拿；留一张 `SIMILAR_DIFF` 覆盖表给自动句不够的对。

毒/可食配对在这个领域是**安全关键字段**，不是趣味字段。校验器加一条：任何 `deadly` 种的 `lookalikes` 里至少有一个非毒种（否则用户从可食种进来看不到警告）。

## 5. 数据补齐

新增字段一览，全部进 `data/mushrooms.json`（唯一真源），`build_data.py` 生成：

| 字段 | 类型 | 来源与写法 |
|---|---|---|
| `idKeys` | `string[3]` | AI 据公开资料写初稿。**每条附 `src`**：优先级 ① 该种 Wikipedia 中/英条目的描述段 ② MushroomExpert.com ③ iNaturalist 分类页摘要 ④ 已选定照片上的可见特征。写法：一句话、现场看得见、不是检索表术语（「菌柄基部有一圈白色杯状菌托」✓，「担孢子 8–10 × 6–7 μm」✗） |
| `colorGroup` | `string[]` 1–3 个 | 按已选照片的主色标注，枚举九色 |
| `silhouette` | 枚举 8 组 | 从 `art.cap` 自动映射 + 人工修正表 |
| `capCm` | `[min, max]` | 从 Wikipedia 描述取（"cap 5–15 cm"），取不到留空则详情页不画尺 |
| `pinyin` / `pyAbbr` / `initial` | string | 自动生成（`pypinyin`），多音字人工修正表 |
| `encounter` | 枚举 4 档 | iNaturalist 全球观察数分档（已有 `census.json`）：≥ 10000 常见 / 1000–9999 偶见 / 100–999 罕见 / < 100 难得一见。**本土种人工修正**：中国块菌 0 条、茯苓 2 条是 iNat 用户少，不是「难得一见」；菜市场买得到的一律不低于「偶见」 |

**⛔ 可靠性要如实写进产品**：关于页和识别要点脚注都说明「识别要点由 AI 据公开资料整理，未经真菌学家审校，仅供学习」。这不是免责套话，是这批数据的真实状态。

同时修四条已发现的过时学名（源数据该更新，验收门已指出）：
`Clitocybe dealbata → Collybia dealbata`、`Psathyrella candolleana → Candolleomyces candolleanus`、
`Lepista sordida → Collybia sordida`、`Hymenopellis raphanipes → Oudemansiella raphanipes`。旧名进 `aka`。

## 6. 答题降级为工具

一期只改入口，二期重构：

- 详情页「测一测」：该种在 `questions_curated` 与生成题里的 4–5 道，复用 `Quiz`。
- 菌菇园流程里的答题**原样保留**，它是抽卡的一部分。
- 二期加「我的 → 认菌训练」：范围闪卡（当前筛选结果出题）/ 易混对决（从 `lookalikes` 出二选一）/ 每日 5 题 / 错题本，奖励是熟练度 0–3 星。

红线不变：食性题题干先给菌名；只有看图题配照片。

## 7. 观察日志「我见过」（二期）

详情页一个按钮，**一次点击当场记一条**（日期 = 今天），再点进去才是编辑（地点、备注）。存档新增 `seen{}` 与 `obs[]`，与 `collections` 独立。

**不做照片，不做任何把用户照片与物种绑定的界面**，这是红线 1。GPS 只写坐标文字，可以做。

## 8. 安全体系

保留全部现有机制，改三处文案，加三处提示：

| 位置 | 改动 |
|---|---|

| 检索结果 | 毒种对照提示（§2 第 4 条） |

## 9. 门禁

每道门加上就反向测一次：故意破坏它守的那条规矩（比如让换 tab 清掉筛选），确认它真的变红并指出是哪一条。不会变红的门只是装饰。

| 门 | 量什么 | 来源 |
|---|---|---|
| `check_data.py` 扩展 | 新字段枚举合法；`idKeys` 恰好 3 条且每条附 `src`；检索表语言启发式（数值范围、希腊字母、μm）；`silhouette` 值必须是绘制代码认得的组；`deadly` 种至少一个非毒相似种 | 现有门扩展 |
| `facet.test.js` | 引擎对拍 | 拷自 skill |
| 行为验收（新） | 换 tab 不清筛选 / 计数与真实结果一致 / 零计数不可点 / 收敛切网格 / 毒种提示出现 / 详情页照片解码且带署名 / 无照片回退绘制 / 页面栈多级返回 / 零 JS 异常 | 仿 `test/verify_photos_ui.mjs`，走真实点击 |
| `core.test.js` | 不变，且内核扫描表不能出现新领域词 | 现有 |

## 10. 分期与方案取舍

三种切法，推荐第一种：

**A. 两期（推荐）。** 一期把「查阅为主」立住：导航、五路检索、详情页、游戏退位、数据补齐、门禁。二期做观察日志、训练重构、离线缓存。数据补齐（543 句）与工程并行，互不阻塞。

**B. 一次做完。** 验收面太大，543 句数据和三块新功能一起上，出了问题分不清是哪层。

**C. 最小改版。** 只换导航、解锁图鉴、做三路检索。快，但没有识别要点，对比网格没内容，详情页还是老样子，等于没改。

## 11. 非目标

- 不做拍照识别（V3 也只做相似度参考 + 剧毒拦截，见 DESIGN.md §0.1）
- 不做「可食」筛选、不做任何通向「能不能吃」的路径
- 不做深色模式（照片在浅底上颜色最准）
- 不做更多语言（引擎按多语言设计，但一期不做）
- 不重写菌菇园
